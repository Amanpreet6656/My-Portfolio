03 / TECHNICAL FAQ

What is offline-first web architecture?

Offline-first web architecture writes all application state mutations to local browser storage (Web Storage API or IndexedDB) before any network call. The app runs fully without an internet connection; network sync is optional, not required.

This eliminates data loss on connectivity failure, ensures deterministic behavior in remote environments, and reduces read latency to near zero once the cache is populated. Projects including BuildLedger Pro (construction payroll in zero-reception sites) and the Smart Kanji Analyzer (offline Japanese linguistic parsing) are built on this constraint.

What are the performance advantages of a dependency-free C++ inference engine over Python-based ML frameworks?

Python ML frameworks (PyTorch, TensorFlow, ONNX Runtime) require gigabytes of runtime (CPython interpreter, CUDA toolkit, shared libraries) that cannot be provisioned on edge microcontrollers. A dependency-free C++ engine compiles to a single static binary and runs on any POSIX target.

Specific advantages in InferC: 64-byte cache line alignment eliminates false sharing during GEMM sweeps; C++17 template metaprogramming resolves all polymorphic dispatch at compile time with no vtable indirection; a zero-copy binary weight format skips deserialization at model load; and no dependency resolution tooling is required at deployment.

What was the core architectural problem Kissa Panjab solved?

Kissa Panjab needed sub-second delivery of high-resolution archival content across network conditions from metropolitan gigabit to constrained rural infrastructure in South Asia, without server-side rendering, database round-trips, or a JavaScript framework boot cycle.

The solution: a fully static, zero-dependency frontend served from CDN edge nodes. No SSR, no hydration, no client-side router. The critical rendering path is one HTML document, one stylesheet, and one deferred script.
